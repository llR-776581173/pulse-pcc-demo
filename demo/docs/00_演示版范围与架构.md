## 1. 两阶段节奏（本次确认）

| 阶段 | 目标 | 口径状态 | 出口 |
|---|---|---|---|
| **A · 演示版** | 用临时默认值 + 合成数据跑通全链路，让交付方看懂整套系统逻辑 | 4 个核心口径 = **占位默认值**（`provisional`），不是已确认口径，也不是不做 | 交付方评审决策点 |
| **B · 正式版** | 交付方认可后，向业务侧收集 4 个核心口径 → 校准 → 上线 | 4 个核心口径 = **业务确认值**（`calibrated`） | 上线 |

**关键**：阶段 A 不是跳过口径，而是把口径**外置成配置**，校准时只改配置与登记值、不改代码。

## 2. 架构四原则（用户已确认）

1. **并行、不替换** — 状态机是新增的独立持久化计算链；现有 `classify_customers(DATA, cut)` 原样继续喂决策板，不是给分类改名。
2. **不推翻六个决策出口** — `C / no_consent / normal / low / high / medium` 定义不变，阈值只影响各出口计数。
3. **状态与价值分层分开** — `value_tier`、`risk_score` 是叠加字段，不参与状态定义；否则会把「价值×偏离」的分组逻辑卷进状态机。
4. **两类日志分表** — `customer_state_transition`（客户状态每天都要算）≠ `decision_log`（人做了决定）；客户状态变化与是否被批准/干预无关。

## 3. 演示版 = 可交互、支持重算的活系统

- **数据**：现有合成数据集（seed `20261026`；6,000 客户 / 118,365 笔 / 25 店 / 窗口 2025-11-01~2026-10-31），**零改动**。
- **重算**：改任一阈值 / 预算 → 状态机快照 + 转移边 + 六出口计数 + 预算券数 + 现金闭环 + 回流统计**全链路重跑**；所有数字由同一 `(rule_version, cut, params)` 派生，不允许出现「状态机说 AT_RISK、决策板说 normal」。
- **页面**：对标商用系统，**不添加任何待校准提示文字**；相关假设、口径占位、发送通道暂未接入等信息**全部现场口述**（见 `01`）。
- **预置案例**：从现有合成数据里筛出的真实客户，非硬编码动画；重算后状态会真实变化（见 `03`）。

## 4. 包含 / 不包含

**包含（同期交付）**
六状态 + 转移矩阵（含两条回流边）／每日快照 + append-only 转移日志／单客户时间轴／
三窗口 `T / [T−W,T] / [T,T+H]` 预警提前天数／干预结果回流／阈值与预算控制面板 + 全量重算／
六出口漏斗联动／状态分布与转移视图／预置案例一键切换／审计抽查／带 `rule_version` 的快照导出。

**不包含（留正式版）**
真实发送通道与频控／权限角色矩阵与 `PUT /api/config` 双签／12 周真实实验与 week16 readout／
监控日报与季度规则更新／PDPO 生产复检／门店可达性系数／03:00 真实调度与运维面。

**明确不做**
不重做决策板、不改现有 API 语义、不改 `net_gain` 排序代理量定位（PRD 明写「不是因果 uplift、不能当 ROI」）、
不引入实时打分 / 移动端 / 顾客端页面。

## 6. 六条红线（重构时不删）

1. 批准 ≠ 发送：`sent_at` 留空，发送时服务端复检 consent。
2. 两层不混：门店告警只诊断 + 人工闸门，不改分组、不自动停券、不判断谁会流失。
3. 规则定金额，AI 只翻译理由；consent lookup 不可被模型绕过。
4. 不同 cut 基线不混用（82.8% @ 4-30 / 78.5% @ 9-30 / 真沉寂 ~55%）。
5. 「不花钱」是带理由、可申诉、可复算的一等决策。
6. **合成数据不得对外表述为真实业务结果** —— 演示版靠「现场口述 + 数据层元数据」共同守住，不靠页面文案（见 `01`、`02`）。
