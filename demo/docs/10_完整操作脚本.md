## 8. 异常兜底速查

| 现象 | 处理 |
|---|---|
| 页面打不开 / 连接被拒 | 确认 8100 进程；`python pulse_app.py 8100` 重启；必要时 `--base=` 复验 |
| 中文乱码、脚本误判 | 按用户提醒启用 `PYTHONUTF8=1`（cmd `set` / Git Bash `export` 或命令前缀） |
| 出现「未接入 / 不是预测模型」 | 打开的是旧答辩页或旧 8000 服务；确认 `http://127.0.0.1:8100/` 与根路由 |
| 案例列表一直「正在加载案例…」 | 刷新页面；查 `GET /api/lifecycle/cases` 是否 200 |
| 「请输入操作人姓名」 | 在 `#cfg-approver` 填姓名后再点「应用并重算」 |
| 「请填写本次调整依据」 | R6 起前端前置校验；在 `#cfg-reason` 填本次调整依据（后端 PRD 4 也要求书面理由） |
| 「未检测到参数改动」 | 确认输入值与默认值**不同**；`applyConfig()` 只收集 `value !== defaultValue` 的字段 |
| 重算后数字没变 | 等「重算中…」消失、确认 `#rver` 已递增；必要时刷新 |
| A 组看不到回流弧线 | R3 起不会发生（首屏 8/8 带弧线）；若发生 → 服务未重启加载新代码，重启 `python pulse_app.py 8100` |
| 审批记录区空白 | R3 起自动加载；若为空点「刷新」，仍空查 `GET /api/audit` |
| 顶部 KPI 区空白 | R4 起自动填充；若为空 → 刷新页面（`renderKpis` 依赖 `GET /api/lifecycle` 200） |
| 左侧导航点击无反应 / 视图不切换 | 强刷页面（Ctrl+F5）排除浏览器缓存旧版；确认页面 script 未被截断 |
| 侧栏折叠后菜单文字消失 | 预期行为（70px 图标条模式）；再点顶部折叠按钮展开 |
| 切换筛选后其它模块也变了 | 不会发生：筛选只作用于当前视图；若疑似串页，检查 `applyViewFilters` 的 view 参数 |
| 某视图内容空白 | 数据由 `boot()` 页载一次性填充、切视图不重新请求；强刷页面或查 `GET /api/lifecycle` / `/api/config` / `/api/audit` |
| logo 不显示 | 确认 `static/img/pcc_logo.svg` 存在且服务从 `pulse_app/` 目录启动；logo 加载失败会自动隐藏占位，不影响功能 |
| `#rver` 不回退到 v1.0 | 规则版本单调递增，属预期行为；把参数改回默认值即可恢复数字 |
